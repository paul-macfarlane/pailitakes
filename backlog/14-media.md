# Epic: Media Uploads (MEDIA)

Real image assets instead of paste-a-URL. Scope settled with Paul 2026-08-27: Vercel Blob storage; upload buttons on the editor's thumbnail and banner fields, and an insert-image button that uploads and drops `![alt](url)` into the body. External `https://` URL paste stays supported everywhere (FR-7.3 amended — was "no in-app upload in v1"). Ref: technical-design.md §5.7.

- [ ] **MEDIA-1** — ADR + design amendments: Vercel Blob (public store) as the image host; upload goes through a server action / route handler (never a client-side token) gated by `canPerformAction(user, Action.ManagePosts)`-style capability; accepted types (`image/jpeg|png|webp|gif`), size cap (~5 MB), server-side sniff of the magic bytes (not just the extension/MIME header); key layout (`posts/{postId}/{uuid}.{ext}`); orphan policy (delete blobs when a never-published post is hard-deleted; otherwise leave — cheap, and public URLs may be linked elsewhere). Amend product-doc.md FR-7.3 and technical-design.md §5.7 + §6 layout; add `BLOB_READ_WRITE_TOKEN` to `.env.example` + `docs/runbooks/environments.md` (staging and prod stores). Provision the Blob store via the Vercel Marketplace flow. _(deps: none)_
- [ ] **MEDIA-2** — `src/lib/media/` domain: `service.ts` (validate → upload → return `{ url, width, height }`) + `data.ts` if a `media_assets` table is wanted for orphan cleanup (decide in MEDIA-1); thin `uploadImage` server action with zod-validated FormData. Unit-test validation (type sniff, size cap, capability gate) with the Blob client mocked. _(deps: MEDIA-1)_
- [ ] **MEDIA-3** — Editor: "Upload" beside the thumbnail and banner URL fields (shadcn `Button` + hidden file input; drag-and-drop optional) that uploads and fills the field; the existing `ExternalImage` preview and `httpsImageUrl` client validation keep working since Blob URLs are `https://`. Progress/error states with theme tokens; mobile-first (camera roll on phones). _(deps: MEDIA-2, ADM-6)_
- [ ] **MEDIA-4** — Body images: an "Insert image" toolbar action in the Markdown editor that uploads and inserts `![alt](url)` at the cursor (prompt for alt text — accessibility). Rendered images in the post body get `loading="lazy"` and, if MEDIA-2 returns dimensions, explicit `width`/`height` to avoid CLS; confirm `rehype-sanitize` still permits `img` with those attrs. Verify a phone-taken (large, EXIF-rotated) upload renders correctly. _(deps: MEDIA-2)_
