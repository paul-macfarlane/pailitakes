- [x] **SEO-8** — Dates display in the **viewer's local timezone**, everywhere. Today every `Intl.DateTimeFormat` in the app is pinned `timeZone: "UTC"` (post-card, post-article, home, home-announcements, comment-item, admin posts/users/moderation/announcements pages, analytics axis) so cached ISR renders can't disagree across viewers — the side effect is that a post published at 8pm ET shows tomorrow's date. Replace the pin with a single shared `<LocalDate>` client island (`src/components`) that renders `<time dateTime={iso}>` with a server fallback and re-formats on the client (`suppressHydrationWarning` on the text node only); delete the per-file `dateFormat` copies. Date-only surfaces (post cards, byline) format `dateStyle: "medium"`; timestamps (comments, admin lists) add time. Analytics axis buckets are UTC-day aggregates and stay pinned — label them as such. Record the reversal of the UTC-pin rationale (ADR-0016 context) in a new ADR. Verify: publish a post after 8pm ET on staging; card, article byline, and admin list all show the same local date. _(deps: none; requested 2026-08-27 by Paul)_
- [x] **SEO-9** — Show the post byline's "Updated" date only when it falls on a different **viewer-local** calendar day than the publish date (a same-day edit renders "Aug 27 · Updated Aug 27" — noise). Extends `showsUpdatedDate` with a `timeZone` + `isSameCalendarDay` check; decided in a `<PostDates>` client island beside `<LocalDate>` since the answer depends on the viewer's zone. Supersedes ADR-0016's "same-day edits show an identical date" consequence (ADR-0028). _(deps: SEO-8; requested 2026-08-27 by Paul)_
