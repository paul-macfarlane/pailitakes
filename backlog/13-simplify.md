# Epic: Feature Simplicity Scan (SIMP)

The site's goal is shipping posts, not the platform (`docs/vision.md`). Step back and ask, feature by feature, what is actually needed, what can be simpler, and what is unused and can go. Scope settled with Paul 2026-08-27: the scan produces a written audit first, then concrete follow-up tasks he approves — it does **not** cut anything in the same pass.

- [ ] **SIMP-1** — Feature audit doc at `docs/audits/2026-08-feature-simplicity.md`. Walk every shipped feature (product-doc.md §3 FR groups + backlog epics 00–12) and classify each as **keep / simplify / drop**, with evidence: analytics dashboard + Neon row counts for usage (comments, likes, announcements, tags, search queries, scheduled archive, revisions if shipped), code footprint (files/LOC/deps per feature, `src/lib` domain size), and maintenance drag (tests, migrations, cron, moderation cost). For each "simplify"/"drop" candidate: what it would remove, what breaks (FRs, ADRs, design-doc sections to amend), migration/data implications, and a rough size. Also flag dependencies that could be dropped outright (e.g. TanStack Query, Recharts, AI moderation) if the feature carrying them goes. End with a ranked recommendation list. Read-only — no code changes. _(deps: none; requested 2026-08-27 by Paul)_
- [ ] **SIMP-2** — Paul reviews SIMP-1 and picks the cuts; file one backlog task per approved item (in the owning epic, appended IDs — e.g. `CMT-n`, `LIKE-n`), each with its ADR + product-doc/design-doc amendments spelled out. Update product-doc.md §6 Future Ideas / Non-Goals for anything demoted. _(deps: SIMP-1; human decision gate)_
